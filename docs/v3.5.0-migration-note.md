# 3x-ui v3.5.0 Migration Note

This document records how the local customizations were rebased from the
v3.4.2-based snapshot onto upstream **v3.5.0**, the decisions taken, the new
fork pin, and the rollback procedure.

## Background

The local repository had a **detached git history**: the customization branch
(`agent/fix-qr-public-address`, 7 commits) shared no common ancestor with
`origin/main`, so a plain `git merge` or `rebase` against upstream was
impossible. The migration therefore rebuilt the customizations on top of a fresh
`v3.5.0` checkout, restoring a shared upstream ancestry.

## What was migrated

Three custom features plus the Xray-core fork dependency:

1. **Per-direction speed limits** (up/down) — Client + ClientRecord fields,
   xray config generation, gRPC `AddUser`, list projection, RHF form inputs.
2. **Per-client session limits** — Client + ClientRecord fields, same data
   flow as the speed limits.
3. **QR/share links use the configured public endpoint** — `preferPublicHost`
   prefers the configured public host unconditionally; settings hints rewritten.

## Xray-core fork pin

The custom Xray-core fork carries per-direction rate limiters and a concurrent
session counter in the dispatcher, plus `UpSpeedLimit`/`DownSpeedLimit`/
`SessionLimit` protobuf fields on `protocol.User` and JSON parsing for those
keys.

The fork was **rebased onto upstream Xray-core v26.7.11** (the version v3.5.0
requires). The only file needing a manual merge was `app/dispatcher/default.go`
(upstream renamed `stats.GetOrRegisterCounter` from a free function to a method
on the stats manager); the fork's insertion points did not overlap with that
rename.

- Fork branch: `agnitum2009/Xray-core` → `custom/ag-v26.7.11`
- Fork commit: `747831e74ddc` (pseudo-version `v0.0.0-20260725032009-747831e74ddc`)
- `go.mod` replace directive points at this commit.

## Rollback

The `backup/pre-v3.5.0-custom` tag is the **immutable** anchor for the previous
working state. It is local and never moved by this migration.

To return to the pre-migration v3.4.2-based custom state:

```
git reset --hard backup/pre-v3.5.0-custom
```

If the local repository itself is unusable, the old state is also on the remote:

```
git fetch agnitum
git checkout f1950ef6
```

To drop customizations and use a vanilla upstream release:

```
git checkout v3.4.2   # previous upstream release
git checkout v3.5.0   # current upstream release
```

Do **not** use the local `main` branch for rollback — it is stale relative to
both upstream and the customization line.

## Keeping the fork replace in sync

If upstream `xray-core` advances again, the fork must be rebased once more
(likely only `app/dispatcher/default.go` will need attention) and the
`replace` line in `go.mod` updated to the new pseudo-version, followed by
`go mod tidy`. The fork branch is `custom/ag-v26.7.11` on
`agnitum2009/Xray-core`.
