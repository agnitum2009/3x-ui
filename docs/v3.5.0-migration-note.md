# 3x-ui v3.5.0 Migration Note

This document is the authoritative technical record of how the local
customizations were rebased from the v3.4.2-based snapshot onto upstream
**v3.5.0**: what changed, why, how it was verified, the key pin values, and how
to maintain it going forward.

For a quick orientation when picking up this repo, read **`HANDOFF.md`** at the
repository root first. For the design semantics and operational behavior of the
speed/session limits, see **`docs/session-limit-handoff.md`**.

## Background

The local repository had a **detached git history**: the customization branch
(`agent/fix-qr-public-address`, 7 commits) shared no common ancestor with
`origin/main`, so a plain `git merge` or `rebase` against upstream was
impossible (`git merge-base` failed). The migration therefore rebuilt the
customizations on top of a fresh `v3.5.0` checkout, restoring a shared upstream
ancestry. After this migration, `git merge origin/main` works normally.

Migration date: 2026-07-25. Result lives on branch `custom/v3.5.0`.

## What was migrated

Three custom features plus the Xray-core fork dependency:

1. **Per-direction speed limits** (up/down) — `UpSpeedLimit`/`DownSpeedLimit`
   on Client + ClientRecord, xray config generation, gRPC `AddUser`, list
   projection, React Hook Form inputs.
2. **Per-client session limits** — `SessionLimit` on Client + ClientRecord,
   sharing the same data flow as the speed limits.
3. **QR/share links use the configured public endpoint** — `preferPublicHost`
   prefers the configured public host unconditionally (browser host is only a
   fallback); settings hints rewritten.

Upstream v3.5.0 does **not** contain any of these features, so all three were
rebuilt fresh on top of it.

## Data flow (speed/session limits)

```
DB clients table                 model.Client (inbound settings JSON)
  speed_limit (legacy mirror)         upSpeedLimit / downSpeedLimit / sessionLimit
  up_speed_limit                          │
  down_speed_limit                        │ ToClient() / ToRecord()
  session_limit                           ▼
        │                          ClientRecord ↔ Client
        │                                │
        │  client_paging.toClientSlim    │  client_crud.Update (UpdateColumns)
        ▼                                ▼
  ClientSlim JSON ←──── list API   inbound settings JSON (persisted)
  (upSpeedLimit etc.)                    │
                                         │ xray.go GetXrayConfig
                                         ▼
                                   xray inbound config entry:
                                   {upSpeedLimit, downSpeedLimit, speedLimit(=down),
                                    deviceLimit, sessionLimit}
                                         │
                                         │ xray.api.AddUser (getOptionalUserUint64)
                                         ▼
                                   gRPC protocol.User{
                                     SpeedLimit: down, UpSpeedLimit, DownSpeedLimit: down,
                                     DeviceLimit, SessionLimit}
                                         │
                                         ▼
                                   FORK dispatcher: per-direction rate limiter
                                   + concurrent session counter
```

**Downlink fallback rule (must stay consistent in all 5 places):** when
`DownSpeedLimit == 0`, the effective downlink falls back to the legacy
`SpeedLimit` value. Applied in: `DownSpeedLimitFromRecord` (model.go),
`xray.go` entry builder, `api.go` AddUser, `client_crud.go` Update, and the
frontend edit-load. `SpeedLimit` (legacy column / JSON key) always mirrors the
resolved downlink so unpatched cores still throttle.

## Xray-core fork pin

session counter in the dispatcher, plus `UpSpeedLimit`/`DownSpeedLimit`/

## Rollback

The `backup/pre-v3.5.0-custom` tag is the immutable anchor for the previous
working state (local + remote).

```
# Return to the pre-migration v3.4.2-based custom state
git reset --hard backup/pre-v3.5.0-custom

# If the local repo itself is unusable
git fetch agnitum
git checkout agnitum/tags/backup/pre-v3.5.0-custom

# Drop customizations, use vanilla upstream
git checkout v3.5.0    # or v3.4.2
```

Do **not** use the local `main` branch for rollback — it is stale.

## Maintenance notes (for future work on this branch)

### Rebasing the fork when upstream xray-core advances

When upstream `xray-core` bumps again, rebase the fork branch
(`custom/ag-v26.7.11`) onto the new upstream commit. Historically only
`app/dispatcher/default.go` needs a manual merge (the `GetOrRegisterCounter`
free-function → method rename was the only overlap). Steps:

1. In the fork repo (`/home/umax/work/3xui/xray-core`), fetch upstream and
   branch off the new commit.
2. Apply the fork's net diff (8 files) via `git diff <old-base> <fork-tip> |
   git apply --3way`; resolve `default.go` mechanically.
3. `go build ./...` + `go test ./common/protocol/ ./app/dispatcher/` in the fork.
4. Commit, push the fork branch, then update the `replace` line in 3x-ui's
   `go.mod` to the new pseudo-version and run `go mod tidy`.

### Regenerating frontend artifacts

After any change to Go models that surface in the API (e.g. adding a
`ClientSlim` field), regenerate:

```
cd frontend
npm run gen      # gen:zod (go run ./tools/openapigen) + gen:api (build-openapi.mjs)
```

Then `npm run build` to refresh `internal/web/dist/` (the embedded frontend).

### Critical invariants (do not break these)

1. **0 means unlimited** for all three limit fields. Persisting a 0 that clears
   a previously-set value requires `UpdateColumns` (see `client_crud.go Update`)
   — a plain save will not write a zero over an existing non-zero.
2. **Downlink fallback** must stay consistent across the 5 places listed in the
   data-flow section, or downlink throttling will disagree between the list
   view, the generated config, and the running core.
3. **React Hook Form**: `ClientFormModal.tsx` uses RHF (not the old useState
   pattern). New form fields go through `<FormField>` and must be added to both
   the `safeParse` whitelist and the `clientPayload` whitelist in `onSubmit`.
4. **protobuf append-only**: fork proto field numbers (6/7/8) must never be
   renumbered, or wire compatibility with already-deployed cores breaks.
5. **SyncInbound field semantics**: the limit fields use unconditional overwrite
   (like `LimitIP`/`TotalGB`), not the guard `if != ""` pattern — this is why
   clearing works without an extra `UpdateColumn`.
